# ASTRA method and disclosure report

## Method

ASTRA is a multi-turn conversational product-retrieval agent for the frozen
50,000-product Clothing, Shoes and Jewelry catalogue. It maintains structured
session state, re-evaluates Buying versus Browsing intent each turn, routes
through an FTS5 keyword path when lexical evidence is sufficient, and otherwise
uses a 150-row dense fallback. Hard eligibility constraints are applied before
ranking. Previously returned products are removed, a fixed top-10 pool is gated
by current-query BGE cosine similarity, and surviving products receive a
rank-preserving diversity pass. When confidence is insufficient, the agent asks
an entropy-selected structured clarification question.

The demonstration runtime contains a gated single-centroid longitudinal memory,
but the official evaluator supplies independent anonymous sessions. It does not
pass the explicit user identity and sequence information required to commit or
read cross-session memory, so final evaluator performance does not rely on
hidden identity inference.

## Models and dependencies

- Local language model: `llama3.1:8b` (`46e0c10c039e`) through Ollama `0.33.2`
- Embedding model: `BAAI/bge-base-en-v1.5`, 768 dimensions, normalized
- Catalogue index: in-memory SQLite FTS5 plus validated precomputed BGE matrix
- Python: `3.13.14`
- Direct Python dependencies: NumPy `2.4.3`, Sentence Transformers `5.6.0`,
  PyTorch `2.12.1`
- External network dependency during evaluation: none after model and artifact
  installation
- Credentials: none
- Provider fallback: none; Ollama is required

## Architecture

```text
official Agent contract
  -> structured state update and live intent
  -> FTS5 AND / weighted-OR candidate routing
  -> session-local hard eligibility masks
  -> BGE current-query scoring and gated memory equations
  -> handcrafted keyword ranking OR s3 dense fallback
  -> seen removal -> fixed top-10 confidence gate -> diversity
  -> recommendations and/or entropy-selected clarification
```

The catalogue/query vectors share one validated embedding-space identifier.
Startup verifies the exact catalogue hash, ASIN row order, product-text
fingerprint, dimension, normalization, and cache metadata. It cannot silently
regenerate or accept a mismatched cache.

## Controlled evidence

The completed confidence-gate ablation preserved Hit Rate@10 at `0.98`, improved
MRR from `0.5566` to `0.6116`, and improved the composite score by `0.010`, while
worsening MTTC by `0.325` turns. This tradeoff must be presented alongside the
gain.

Long-term-memory evidence is not claimed as a performance improvement. The
trustworthy archived evaluator found that relevant-set MRR decreased from
`0.021452` without memory to `0.019327` with memory at its frozen configuration,
even though the relevance gate achieved ROC AUC `0.97`. The adaptive update has
not passed the required dormant-interest evaluation.

## Reliability

- Provider selection is frozen to BGE/Ollama in the evaluator entry module.
- Catalogue embedding generation is disabled during startup and evaluation.
- Model calls retry once on transport or invalid-response failure.
- Failed turns roll back session state.
- Conversation state is isolated by evaluator session ID.
- The official evaluator is executed unchanged by the included launcher.

## Limitations

- Ollama and `llama3.1:8b` must be installed and running locally.
- The large BGE catalogue cache must be downloaded separately and match the exact
  organizer catalogue.
- There is no provider fallback if Ollama is unavailable.
- LLM state editing adds latency and can still fail after its retry.
- Keyword scoring contains handcrafted weights and known substring-matching edge
  cases.
- The confidence gate can improve rank quality while delaying first hit.
- The one-centroid memory representation cannot retain distinct user interests;
  current evaluation does not support a memory-improvement claim.
- Official independent sessions do not exercise the demo's explicit longitudinal
  identity lifecycle.
